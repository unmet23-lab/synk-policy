AI한테 영상 움직임을 맡길 때, AI 티 안 나게

영상 「AI한테 "트렌디하게" 시켰더니 더 AI 같아졌어요」

「트렌디하게」라고만 시키면 낱말마다 튀고 형광펜 긋고 숫자를 세는 효과를 전부 넣어요. 많이 본 소개 영상 넷을 뜯어보니 반대였어요 — 글자는 가만히 두고, 움직이는 건 화면 속 입력과 카메라. 그 차이를 다섯 줄로 붙여요.

빈칸 채우기 선택 · 채운 대로 복사돼요. 이 화면 밖으로 보내거나 저장하지 않아요

프롬프트

넣는 곳 · 채팅 AI · 코딩 AI 어디든 — 움직임을 맡기는 요청 끝에 붙이기

이 영상의 움직임(모션)은 아래 다섯 줄을 지켜 줘.
1. 글자는 줄 단위로만 나오게 — 낱말·글자마다 튀지 않게
2. 강조색은 한 화면에 한 곳만
3. 장면 전환은 컷 — 페이드는 끝 화면에만
4. 움직임은 클릭·입력·화면 확대가 맡게
5. 빼기: 튕김 · 흐림 등장 · 형광펜 · 숫자 세기
코드로 만든다면 숫자도 지켜 줘: 글자 등장 10프레임(30fps), 곡선 cubic-bezier(0.23, 1, 0.32, 1), 줄마다 3프레임씩 늦게, 화면은 장면 내내 1.00 → 1.04배로 천천히 밀기.

내 PC에서 몰래 많이 쓰는 프로그램 찾기

영상 「제가 나눠 드린 도구가 한 시간에 4.3GB를 쓰고 있었어요」

제가 나눠 드린 세션 공유 도구가 한 시간에 4.3GB를 쓰고 있었어요. 기록이 바뀔 때마다 0.15초 안에 다른 폴더 28곳으로 복사했거든요. 5분씩 모아 옮기게 바꾸자 시간당 94MB가 됐어요. 내 PC에도 이런 프로그램이 있는지 1분이면 찾아요.

빈칸 채우기 선택 · 채운 대로 복사돼요. 이 화면 밖으로 보내거나 저장하지 않아요

체크리스트

넣는 곳 · 직접 — 윈도우 작업 관리자

  1. Ctrl+Shift+Esc로 작업 관리자를 열어요
  2. 「세부 정보」로 가요
  3. 열 이름 줄을 오른쪽 클릭 → 「열 선택」
  4. 「I/O 쓰기 바이트」에 체크해요
  5. 그 열 이름을 눌러 큰 순서로 — 켜진 뒤 쓴 양의 합이라, 숫자가 빨리 느는 것을 봐요

프롬프트

넣는 곳 · 코딩 AI — 윈도우에서 PowerShell을 돌릴 수 있는 것

내 윈도우 PC에서 지금 가장 많이 쓰는(I/O 쓰기) 프로그램을 찾아 줘. PowerShell로 프로세스마다 지금까지 쓴 바이트(Win32_Process의 WriteTransferCount)를 재고, 60초 뒤에 한 번 더 재서 그 사이에 쓴 양을 구해 줘. 큰 순서로 다섯 개를 표로 보여 줘(이름 · 프로세스 ID · 쓴 MB · 한 시간으로 늘리면 몇 MB). 1등이 무슨 프로그램이고 왜 그만큼 쓰는지 짐작되는 까닭과 줄이는 방법도 알려 줘. 아무것도 끄거나 지우지는 마.

직접 돌려 봤어요 10월 22일, 코딩 AI에 붙여 넣어 보니(간격은 30초로) 두 번 잰 차이로 다섯 개 표를 냈고, 1등 프로그램이 작업 폴더마다 임시 파일을 계속 만들었다 지우는 것까지 짚었어요. 이 값은 디스크뿐 아니라 모든 쓰기를 합친 것이라는 점도 함께 알려 줬어요.

2026.10.24프롬프트 + 명령곧 나올 영상

내 쇼츠, 몇 초가 멈춰 있는지 재기

영상 「42초 쇼츠, 재 보니 24초가 멈춰 있었어요」

42초짜리 쇼츠를 재 보니 24초가 화면이 거의 안 바뀌는 시간이었어요. 목소리가 계속 나오면 만든 사람은 못 느껴요. 기준은 둘 — 거의 멈춘 시간이 전체의 15% 이하, 한 번에 1.5초 넘게 멈춘 곳은 없게(끝 화면은 빼고).

빈칸 채우기 선택 · 채운 대로 복사돼요. 이 화면 밖으로 보내거나 저장하지 않아요

프롬프트

넣는 곳 · 코딩 AI — 내 영상 파일을 열고 명령을 돌릴 수 있는 것

【내 영상 파일】에서 화면이 거의 안 바뀌는 시간을 재 줘. 셈은 이대로 해 줘 — ffmpeg로 가로 270픽셀로 줄이고 tblend=all_mode=difference와 signalstats로 프레임마다 앞 프레임과의 밝기 차이 평균(YAVG, 0~255)을 뽑아. 그 값을 프레임 시각(pts_time)으로 0.5초 칸에 넣어 칸마다 다시 평균 내고, 0.15보다 작은 칸을 '거의 멈춤'으로 봐 줘. 거의 멈춘 칸이 이어지는 구간을 표로 보여 주고, 전체에서 그 시간이 몇 %인지, 1.5초 넘는 구간이 어디인지 알려 줘. 영상 끝까지 이어지는 구간은 끝 화면으로 따로 표시해 줘.

명령

넣는 곳 · 직접 — 터미널(ffmpeg가 깔려 있을 때)

ffmpeg -i 【내 영상 파일】 -vf "scale=270:-1,tblend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=diff.txt" -an -f null -

diff.txt의 YAVG 값을 0.5초씩 평균 내서 0.15보다 작으면 「거의 멈춤」이에요.

직접 돌려 봤어요 10월 22일, 이 편을 만들 때 쓴 첫 판(41초, 중간에 2초 멈춘 곳이 있던 판)을 코딩 AI에 붙여 넣어 보니 거의 멈춘 시간 12% 안팎, 1.5초 넘는 구간 둘(7.0~9.0초 · 끝 화면)을 찾아 우리 측정 도구와 같은 숫자를 냈어요. 셈 방법을 적지 않은 첫 판 프롬프트는 AI마다 셈이 달라 20%로 나와서, 지금처럼 방법을 못박았어요.

GitHub 자동 검사가 빨간불일 때, 코드 탓인지 무료 분 탓인지 가르기

영상 「GitHub 무료 2,000분이 바닥나자, 자동 검사가 2초 만에 꺼졌어요」

비공개 저장소의 GitHub Actions 무료 분(Free 계정 기준 한 달 2,000분)을 다 쓰자, 검사가 실패가 아니라 시작도 못 하고 1~3초 만에 끝났어요. 단계에서 실패했으면 코드부터, 단계 0개 · 몇 초 만에 끝났으면 한도부터 보면 돼요.

빈칸 채우기 선택 · 채운 대로 복사돼요. 이 화면 밖으로 보내거나 저장하지 않아요

프롬프트

넣는 곳 · 코딩 AI — 내 저장소 폴더에서 gh 명령(GitHub CLI)을 돌릴 수 있는 것

이 저장소의 GitHub Actions 실행 가운데 최근 30개를 보고, 실패한 실행을 둘로 갈라 줘.
- 단계에서 실패한 실행: 코드 쪽 문제. 실패한 단계 이름과 오류 첫 줄을 적어 줘.
- 단계가 하나도 돌지 않았거나 몇 초 만에 끝난 실행: 한도·결제 쪽 문제. 그 실행에 붙은 안내 문구를 원문 그대로 적어 줘.
실행 번호 · 시각 · 걸린 시간 · 갈래 · 근거를 표로 보여 주고, 한도 쪽이 있으면 남은 무료 분을 GitHub 어디서 보는지도 알려 줘. 아무것도 다시 돌리거나 고치지는 마.

체크리스트

넣는 곳 · 직접 — GitHub 웹

  1. 남은 무료 분: GitHub에 로그인 → 설정의 빌링 화면(주소 끝이 settings/billing). 조직 저장소면 조직 설정의 Billing & Licensing
  2. 무료 분은 매달 1일에 다시 채워져요
  3. 공짜로 다시 돌리는 길 ①: 감출 게 없는 저장소라면 공개로 — 공개 저장소의 표준 실행기는 무료예요(공개 전에 비밀값·개인정보부터 확인)
  4. 공짜로 다시 돌리는 길 ②: 비공개로 둬야 하면 내 PC를 자체 실행기(self-hosted runner)로 — 공개 저장소에는 붙이지 않아요(남이 보낸 코드가 내 PC에서 돌 수 있어요)

직접 돌려 봤어요 10월 22일, 우리 비공개 저장소에서 「10월 20일 19시부터 10월 22일 0시까지(한국 시각)」로 붙여 넣어 보니 실패 22건을 한도·결제 21건(단계 0개 · 2~8초 · 모두 같은 안내 문구)과 코드 1건(시험 16개 실패)으로 갈랐어요. 영상에서 센 0단계 실행 18번과 빨간 시험 16개가 그대로 들어 있었어요.
